# مكتبة الوراق | Al-Warraq Library

مشروع كامل: **واجهة أمامية** (HTML/CSS/JS بلا بناء) + **خادم** (Python FastAPI) + **قاعدة بيانات** (SQLite).
يعرض فهرساً بحجم **كل فهرس غوتنبرغ (نحو 75,000 كتاب)** من مشروع غوتنبرغ (ملك عام) مع تصنيفات ومؤلفين مشهورين،
وقسماً لروابط البحوث الطبية والهندسية المفتوحة. الواجهة بالعربية والإنجليزية.

```
backend/
  app/main.py        واجهة API وتقديم الموقع
  app/db.py          قاعدة SQLite والبيانات المنتقاة (386 كتاباً، 146 مؤلفاً)
  app/importer.py    استيراد فهرس غوتنبرغ الرسمي
  app/bootstrap.py   يعمل قبل الخادم: إنشاء الجداول + الاستيراد لأول مرة
  app/research.py    مصادر البحوث الطبية والهندسية
  app/data/          authors.txt و books.txt (قابلة للتعديل)
  tests/             اختبارات الـ API والاستيراد
frontend/            index.html + style.css + app.js
Dockerfile, docker-compose.yml
```

## التشغيل بـ Docker (الأسهل)
```bash
docker compose up -d --build
```
افتح http://localhost:8000. عند أول تشغيل ينزّل الخادم فهرس غوتنبرغ (يحتاج إنترنت) ويستورد كل الكتب
(يستغرق نحو دقيقة). البيانات تُحفظ في volume باسم `warraq-data` فلا يتكرر الاستيراد.

## التشغيل بدون Docker
```bash
./run_local.sh          # يحتاج Python 3.9+
```

## النشر على الإنترنت
- **سيرفر (VPS) + نطاق:** شغّل `docker compose up -d --build` ثم ضع Caddy أمامه:
  ```
  library.example.com {
      reverse_proxy localhost:8000
  }
  ```
  (Caddy يجلب شهادة HTTPS تلقائياً.)
- **Railway / Render / Fly.io:** انشر المستودع كخدمة Docker، وأضف قرصاً دائماً (volume) مُركَّباً على `/data`.
  المنصة تضبط `PORT` تلقائياً والـ Dockerfile يقرأه.

## إعدادات (متغيرات بيئة)
| المتغير | الافتراضي | الوصف |
|---|---|---|
| `AUTO_IMPORT` | `1` | استيراد غوتنبرغ عند أول تشغيل |
| `AUTO_WIKISOURCE` | `1` | استيراد ويكي مصدر العربية (نحو 43 ألف قصيدة وكتاب) عند أول تشغيل |
| `IMPORT_LIMIT` | `0` | عدد الكتب (0 = الكل) |
| `IMPORT_LANGS` | (الكل) | تقييد اللغات، مثل `en,ar,fr` |
| `WARRAQ_DB` | `backend/data/warraq.db` | مسار قاعدة البيانات |

إعادة الاستيراد أو تغيير العدد يدوياً:
```bash
cd backend && python -m app.importer --lang en,ar
# أو من ملف نزّلته: python -m app.importer --csv pg_catalog.csv
```
الاستيراد آمن للتكرار: يستبدل الكتب المستوردة فقط ويُبقي المنتقاة.

## واجهة API
| المسار | الوصف |
|---|---|
| `GET /api/books?q=&cat=&org=&ak=&au=&sort=def\|t\|a&bl=&ui=ar\|en&offset=&limit=` | بحث وتصفية وترقيم الصفحات (`au` = اسم المؤلف كما هو) |
| `GET /api/meta` | التصنيفات والمؤلفون مع الأعداد |
| `GET /api/shelf` | كتب رف الغلاف في الصفحة الرئيسية |
| `GET /api/research?domain=med\|eng&q=` | روابط بحث جاهزة في قواعد البحوث المفتوحة |
| `GET /api/cover/{id}` | غلاف من المكتبة المفتوحة (يُحفظ في القاعدة) |
| `GET /api/health` | فحص الحالة |

وثائق تفاعلية: `/docs`.

## ملاحظات قانونية
- الموقع لا يستضيف ملفات كتب. كل رابط يقود إلى المصدر الأصلي (غوتنبرغ، أرشيف الإنترنت، المكتبة المفتوحة، ويكي مصدر، وقواعد الأبحاث).
- الملك العام يختلف من بلد لآخر (غوتنبرغ يتبع القانون الأمريكي). راجع قانون بلدك قبل أي إعادة نشر.

## الأغلفة
الكتب التي لها رقم في غوتنبرغ تُحمَّل أغلفتها مباشرة من غوتنبرغ. وإن لم يوجد غلاف يسأل المتصفح الخادم،
فيبحث في المكتبة المفتوحة (Open Library) مرة واحدة ويحفظ النتيجة لكل الزوار. وإن لم يوجد شيء يظهر غلاف مصمَّم باسم الكتاب.

## ترقية من نسخة سابقة
احذف الملف `backend/data/warraq.db` ثم شغّل `python -m app.bootstrap` من جديد، فيعاد بناء القاعدة بالفهرس الكامل.

## الوصول إلى 500 ألف كتاب (HathiTrust)
غوتنبرغ وحده نحو 75,000 كتاب. لإضافة مئات الآلاف:
1. من صفحة https://www.hathitrust.org/hathifiles نزّل ملف الفهرس الكامل `hathi_full_YYYYMMDD.txt.gz` (نحو 1 جيجابايت، لا تفكّه).
2. ضعه في مجلد المشروع، ثم من داخل `backend`:
```bash
python -m app.importer --hathi ../hathi_full_20260101.txt.gz --hathi-limit 450000
```
يقرأ الملف على دفعتين ولا يحتاج ذاكرة كبيرة، ويأخذ بضع دقائق. يضيف الكتب المتاحة للعرض الكامل في العالم كله فقط
(`access=allow` و`rights=pd`) ويتجاوز المكرر وما هو موجود من غوتنبرغ.
مع Docker: ضع الملف في مجلد المشروع وفعّل في `docker-compose.yml` السطرين `HATHI_FILE` و`volumes` الموضحين فيه.

> الأغلفة من HathiTrust تُجلب من رابط الغلاف الرسمي عندهم، وإن لم تظهر يستخدم الموقع المكتبة المفتوحة ثم الغلاف المصمَّم.

## الشعر والكتب العربية (ويكي مصدر)
يستورد الخادم عند أول تشغيل قائمة أعمال ويكي مصدر العربية من Wikidata: نحو 41 ألف قصيدة لكبار الشعراء ونحو 1,500 كتاب
ورسالة ووثيقة، ولكل منها رابط قراءة مباشر في ويكي مصدر. لإعادة الاستيراد (آمن للتكرار):
```bash
cd backend && python -m app.wikisource
```

## البحث السريع
البحث يستخدم فهرس نصوص كاملة (SQLite FTS5 بمقطّع trigram) فيجد أي جزء من الكلمة كما في السابق، لكن في أجزاء من الثانية.
الفهرس بنسخته الخفيفة (`detail=none`): نحو 100 ميغابايت لمليون كتاب بدل 310، وبالنتائج نفسها.
يُبنى الفهرس تلقائياً مرة واحدة عند التشغيل (نحو دقيقة لمليون كتاب) ويبقى محدَّثاً مع كل استيراد،
وقاعدة بيانات فيها الفهرس القديم الأكبر تُحوَّل وتُضغط (VACUUM) تلقائياً عند أول تشغيل.
الكلمات الشائعة جداً (أكثر من 10,000 نتيجة) يظهر عددها «أكثر من 10,000».

## الأمان
الحمايات الموجودة في الخادم ([backend/app/security.py](backend/app/security.py)):
- **حد للطلبات لكل عنوان IP** في الدقيقة (مثلاً 20 بحثاً في الأبحاث، و300 طلباً عاماً)، ويُرجِع 429 عند التجاوز.
  `RATE_LIMIT_SCALE=2` يضاعف الحدود، و`0` يلغيها.
- **رفض طلبات POST القادمة من مواقع أخرى** (حماية CSRF لأزرار الإعجاب والعدادات).
- **ترويسات أمان على كل صفحة:** Content-Security-Policy (صفحات الكتب بـ nonce لكل طلب)، ومنع التضمين في إطار،
  و`nosniff`، وReferrer-Policy، وHSTS عند HTTPS.
- **روابط الخدمات الخارجية** (OpenAlex وويكيبيديا) لا تصل إلى الصفحة إلا إن كانت `http(s)`.
- **العدادات العامة لا يمكن تضخيمها:** المشاهدة تُحسب مرة لكل زائر في اليوم، والبحث مرة لكل زائر،
  ولا يظهر بحث في «الأكثر بحثاً» قبل أن يبحث عنه 3 أشخاص مختلفين.
- **حدود على المدخلات:** طول البحث 200 حرف، وأعمق صفحة 100,000.
- **الحاوية تعمل بمستخدم عادي لا root**، والمنفذ 8000 مفتوح لهذا الجهاز فقط (الجمهور يمر عبر Caddy وHTTPS).

في الإنتاج اضبط أيضاً:
| المتغير | مثال | السبب |
|---|---|---|
| `SITE_URL` | `https://library.example.com` | الروابط الأساسية وخرائط الموقع لا تعتمد على ترويسة Host |
| `ALLOWED_HOSTS` | `library.example.com` | رفض أي اسم نطاق آخر |
| `FORWARDED_ALLOW_IPS` | `*` (مع docker-compose) | معرفة عنوان الزائر الحقيقي خلف الوكيل، للحدود والعدادات |

> ترقية من نسخة Docker سابقة كانت تعمل بـ root: نفّذ مرة واحدة
> `docker compose run --rm -u root web chown -R 10001 /data`.

## الظهور في محركات البحث (SEO)
ما يقدّمه الموقع للزواحف ([backend/app/seo.py](backend/app/seo.py)):
- **صفحات ثابتة يقرؤها أي زاحف:** لكل تصنيف `/category/his` ولكل مؤلف `/author/shakespeare`، بالعربية والإنجليزية (`?lang=en`)،
  مع روابط لكل كتاب وترقيم صفحات. وكل كتاب له صفحته `/book/<id>/<slug>`.
- **خريطة الموقع** `/sitemap.xml`: الصفحة الرئيسية والتصنيفات والمؤلفون، وكل الكتب (أكثر من مليون رابط في ملفات من 40,000).
- **`robots.txt`** يسمح بقراءة الموقع والـ API (الصفحة الرئيسية تُملأ منه)، ويمنع العدادات فقط.
  ونتائج الـ API تحمل `X-Robots-Tag: noindex` فلا تظهر في نتائج البحث.
- **بيانات منظَّمة (JSON-LD):** WebSite مع مربع بحث، وOrganization مع الشعار، وBook وBreadcrumbList لكل كتاب،
  وCollectionPage لكل تصنيف، وProfilePage لكل مؤلف.
- **روابط أساسية (canonical) وhreflang** للعربية والإنجليزية، ووسوم Open Graph وTwitter مع صورة مشاركة `og-image.png`.
- **أيقونات** favicon.ico وأيقونات الجوال وملف `manifest.webmanifest`.

### بعد نشر الموقع على نطاقك
1. اضبط `SITE_URL=https://نطاقك` حتى تكون كل الروابط في الخرائط والصفحات بنطاقك الحقيقي.
2. **Google:** أضف الموقع في [Google Search Console](https://search.google.com/search-console)، واختر التحقق بوسم HTML،
   وضع الرمز في `GOOGLE_SITE_VERIFICATION`، ثم أرسل الخريطة `https://نطاقك/sitemap.xml`.
3. **Bing:** أضفه في [Bing Webmaster Tools](https://www.bing.com/webmasters) (يمكن استيراده من Google مباشرة)،
   أو ضع رمز التحقق في `BING_SITE_VERIFICATION`. وYandex عبر `YANDEX_VERIFICATION`.
4. **IndexNow (فهرسة فورية في Bing وYandex وغيرهما):** ضع في `INDEXNOW_KEY` نصاً عشوائياً من 32 حرفاً (أرقام وa-f)،
   فيقدّم الموقع ملف المفتاح تلقائياً، ثم نفّذ:
   ```bash
   cd backend && python -m app.seo indexnow          # الرئيسية والتصنيفات والمؤلفون
   python -m app.seo indexnow --books                # وكل صفحات الكتب
   ```
